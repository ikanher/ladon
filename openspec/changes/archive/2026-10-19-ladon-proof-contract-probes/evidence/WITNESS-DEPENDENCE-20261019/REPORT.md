# Witness-dependence v2 qualification

Ladon now supports a narrow source-bound witness-dependence probe. It recognizes only the original-order forms `∃ w : Nat, ∀ x : Nat, P(w,x)` and `∀ x : Nat, ∃ w : Nat, P(w,x)`, with the same typed predicate declaration and each contract's permissions aligned to its own telescope. It keeps `witness-dependence-v1` on the historical unsupported path for native replay compatibility.

The frozen 17-case v2 suite covers binder order and identities, exact argument roles, typed symbol mapping, per-reading permissions, source ownership, shared context, goal order, digest integrity, and the v1 replay route. Full regression exposed an older profile test that still expected witness dependence to be unimplemented. The original test is preserved; its v2 replacement changes that catalog expectation while retaining the CLI immutability check. The replacement and witness suites pass **20/20**. The global test-freeze board verifies **118 records** with no hash mismatches.

Final-code source qualification used the previously extracted closed Lean application `WitnessProbe.weak ()`, whose type is `∀ x : Nat, ∃ w : Nat, WitnessProbe.P w x` for `P w x := x ≤ w`. Under a fresh 30-minute window, the source-bound right-to-left discrepancy and the cross-order strong-to-weak implication control both passed their `formal-reading` and complete `probe` goals: **4/4 Lean checks** accepted in 165.004 seconds. Each check has completed replay and accepted trust; raw evidence hashes match the referenced evidence. Planned artifacts retain open goals and no checker authority. The independent audits on board posts [board excerpts](BOARD-EXCERPTS.jsonl), posts #757, #759, #761 and #764 found no actionable code issues, verified the earlier source evidence, caught the weak-to-weak initial control, and then accepted the replacement strong-to-weak control and final-code receipts.

The repository-wide test run reached **1,796 passed and 2 failed** before it was interrupted at 30 minutes. Both failures were stale assertions: the probe-profile expectation changed when v2 was registered, and the installed-CLI test still expected the old memory-limit wording. Each original was preserved and superseded through the test board; the replacement profile, witness, and memory-limit cases pass **23/23**. The full suite was not rerun after the helper-only quality refactor and these test supersessions. After those edits, the repository strict-quality scan reported no issues, Ruff passed over `src`, `tests`, and `scripts`, and `compileall` passed.

One qualification accounting limitation remains: the source extraction response reports an internal `secondsPerProcess: 60` setting while the outer supervised extraction request is capped at 30 seconds. The observed Lean source processes completed in under 1.4 seconds, and the outer worker, planning, and checking stages all recorded the requested 30-second, 12-GiB RSS, and 8-MiB output limits. This metadata inconsistency is retained in the evidence rather than hidden.

This establishes one constructed, authored Nat example and one logical implication control. The source fidelity remains `attributed-unreviewed`; no natural-language fidelity, PDE correctness, Navier–Stokes exposition detection, held-out detection benefit, or whole-method claim follows. Three of the five probe families now have implementation evidence; restricted-domain and inequality-direction families, the five-fault/five-control gate, and wider integration remain open. Child progress stays 1/8 and umbrella progress 2/12. Nothing was pushed.
