# Proposal

## Why

Retest-5 exercised native prose/Lean correspondence but silently lowered intended real fractions using natural division, could not transport scoped Unicode names, and spent minutes replaying each small correspondence. The run stopped at 57.65 minutes of a 90-minute budget while `finish` still returned `continue`; no mathematical error in the paper was established.

## What Changes

- Preserve declared operand/result types through expression lowering and expose the actual elaborated subject for review. Reject semantic disagreement rather than proving a different proposition.
- Transport observed local contexts by binder identity, supporting the recorded Unicode/subscript and shadowing cases without renaming primary source or borrowing hypotheses.
- Instrument correspondence stages, reduce demonstrated repeated work within one checked request, and produce compact ordinary outputs without weakening replay, freshness, trust, or resource limits.
- Add explicit checkpoint/finalization records and an executable continuation protocol: an unfinished queue with time remaining cannot become an ordinary finalized run merely because a report was written.
- Reproduce the recorded failures and replay portable controls plus selected real-source obligations. Preserve original reports and first responses. Measure operational improvement separately from mathematical detection.

The bounded outcome is a reliable local correspondence path: faithful typed goals, supported identity-based context transport, measured replay cost, and truthful stopping records. Four implementation packages plus a shared qualification gate are defined in `work-packages.md`. No new full-paper run, release, archive, or manuscript edit belongs to this umbrella.

## Capabilities

### New Capabilities

- `ladon-correspondence-lowering-integrity`: agreement between structured types, emitted expressions, and observed Lean elaboration.
- `ladon-correspondence-context-transport`: identity-based reconstruction of actual formal local contexts for connecting obligations.
- `ladon-correspondence-execution`: bounded, measured request-local reuse and compact delivery of replay evidence.
- `ladon-investigation-finalization`: separate checkpoints, continuation obligations, authorized stopping records, and finalization receipts.

These are additional requirement owners; the canonical spec inventory has no correspondence capabilities yet. They refine the completed but unarchived `ladon-nl-lean-correspondence-umbrella` without copying or replacing its pending requirements. Its interpretation, proof-slice, checking, and review contracts remain baseline obligations. Canonical native-v3 validation and observation-authority contracts remain unchanged.

### Modified Capabilities

None in the current canonical spec store. If implementation requires changing a canonical payload contract, explicitly revise this packet's delta and version policy before making that change; do not silently reinterpret existing artifacts.

## Impact

Primary owners are `correspondence_interpretation.py`, `correspondence_check.py`, `correspondence_maps.py`, scoped slice helpers/validators, native correspondence payload/projection consumers, and investigation CLI/status/reporting. Existing source-goal capture/completion, supervisor, and environment checks remain authority-bearing dependencies. The implementation fingerprint must include any new semantic helpers.

New interpretation/transport semantics require new identities and fresh checks/reviews; historical artifacts retain their original meaning and results. Existing v1/v2 investigation behavior and native canonical identities are preserved. Ladon remains usable without Quux or a model service. No dependency additions or broad compiler/parser redesign are planned.

Source-first evidence and hashes are in `evidence/BASELINE.md` and `evidence/baseline.json`. Planning does not claim any defect has been fixed or the target-paper issue detected.
