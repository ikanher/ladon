# Frozen qualitative read/find/check fixture r49

This development fixture implements the October 4 external starter review's
first recommendation: inspect a real mathematical claim, discover a supporting
lemma, and explicitly check its proposed use in two new-goal contexts. It is not
a held-out benchmark or human-comprehension study.

The installed initial candidate remains `15835d5f0a499e13d658c5bf26933c8456f0e37c`.
The existing r44 canonical capture, r45 component assessments and r47 guide retain
their original dates/identities. The r48 product bundle remains unchanged. The
new selection adds the already validated 26-row assessment companion and its
original source, both explicitly permitted. This reconciles the guide's references
to “supplied assessments”; no new correspondence approval is inferred.

- `bundle-selection.json`: exact full-file disclosure choices for the new fixture.
- `input-identities.json`: original inputs and the preserved r48 archive identity.
- `reader-task.json`: task, exact goal, ordered contexts, trusted pinned environment,
  finite commands/time/RSS limits. It supplies no lemma name or answer key.
- `synthetic/`: unchanged illustrative finite-map files plus a separately labeled
  stale explanation-review variant. None is a real review of the exposition.
- `fixture-verification.json`: operator preparation, complete inventory/digests,
  companion validation and historical-evidence preservation checks.

Working artifacts, the complete product bundle and extracted evidence reside at
`/home/codex/.cache/ladon-reader-loop-r49/shared/`. The byte identities are frozen
in the verification record. Ladon and plain-tooling readers receive exactly those
same mathematical materials and run in fresh contexts on the same model/effort.
This instruction-level isolation is not OS confinement. The plain reader's command
recorder uses the installed process-supervision helper for telemetry only; its
mathematical task uses ordinary files and pinned Lean tools.

Initial attempts are retained before repairs and fresh retests. Every
task command is recorded with argv, stdout/stderr, exit, elapsed time, sampled
process-tree RSS and finite timeout/memory/output limits. Sources and compiled
artifacts in the neighbor Lean repository are read-only; scratch is separate.
No full Lake build or new Lean capture is required just to read the bundle.

Completion requires correct scope, evidence distinctions, explicit fresh
application results and a concrete account of navigation/decision/error-avoidance
value. Rejection or a missing premise does not prove a goal false. Failures and
workarounds remain in the reports. Quantitative benefit metrics, human cohorts,
process provenance and community profiles remain deferred.
