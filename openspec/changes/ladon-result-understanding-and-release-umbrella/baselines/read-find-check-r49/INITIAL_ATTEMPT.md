# Initial paired attempt: useful checks, failed ordinary discovery

Two fresh Luna-medium reader contexts received the same frozen exposition,
manifest, authored guide, assessment companion, canonical evidence, source
files and task. Neither received the review packet's answers or a selected
lemma. This was instruction isolation, not filesystem confinement. The supplied
runtime was the historical qualified r48 candidate; fixture reconciliation
did not qualify new code.

Both readers independently selected
`Mf.DP.fixedEpochCenterGap_pos_of_boundary_nonneg` and recognized that the
nearby application needs the boundary-gap nonnegativity premise. The Ladon
reader's direct explicit-pinned checks accepted context A and returned a
residual obligation for context B. The plain reader's combined Lean command
reported the missing premise in B. A separately recorded operator supplement
compiled A alone and printed its axioms; that supplement is not an original
reader success.

The task did **not** pass the qualitative acceptance gates. Ladon's reader
inspected the extracted manifest without its canonical artifacts, guide or
assessments. It did not navigate the supplied complete `result.zip`. The CLI
correctly reported unresolved targets for that incomplete invocation, but the
reader incorrectly generalized this to all supplied evidence. The operator's
ordinary bundled inspection resolves all 25 targets and includes the selected
assessments. Original reader reports retain their incorrect conclusion.

Both summaries also contain headlines that mingle average-only exposition
with formally linked transcript conclusions, despite qualifications elsewhere.
The complete prose inequality must not inherit a partial component's formal
resolution status. These are substantive scope errors, not just style issues.

Discovery first failed because the reader omitted the root required by its
chosen scope. After correcting that invocation, it still returned an
operational failure. The operator's JSON reproduction identifies
`invalid-batch-worker-output`: a structurally mismatched type for `hNonFull`.
Diagnostic-only instrumentation retained the authentic helper context while
calling the unchanged validator and preserving the failure. The valid
displayed hypothesis is `point.epoch < point.horizon`; the serialized type
contains projection constants and the internal free-variable identity for
`point`. Direct universal candidate checking accepts the same mathematical
context. This core discovery defect takes priority over presentation features.

The Ladon reader recorded 28 commands against a 24-command limit and required
a root stop instruction. That intervention supplied no mathematical guidance.
One initial task read was outside the recorder and immediately repeated inside
it. The plain reader recorded 15 commands and repaired a missing Mathlib import
path using existing compiled package directories. No shared source or build was
modified. These departures prevent a claim of an unassisted, clean completion.

Recorded command totals and tree RSS are in `initial-observations.json`. They
include failed and administrative commands and do not measure complete reader
wall-time or a controlled speed comparison. The maximum recorded tree RSS was
about 8.35 GiB for Ladon and 6.47 GiB for plain tooling, within the 32 GiB limit.
The two arms performed different operations; these figures do not establish
relative performance.

## Subsequent application contradiction

The projection-only repair passed clean candidate qualification and 830
installed semantic/discovery/result tests on each supported Python runtime.
It nevertheless failed the real field replay with scratch compilation enabled.
The helper reported `accepted` and emitted an application using `h` for the
`boundary` argument. The subsequent compiler correctly rejected
`hBoundaryNonneg : 0 ≤ boundary` where that term required `0 ≤ h`.
The original reader's direct context-A output contains the same malformed
application. Its accepted label therefore does not establish a successfully
compiled application. The separately compiled plain-tooling context-A proof
uses the correct argument and remains valid.

This is a second core dependency defect, not a failure of the mathematical
lemma. An isolated, explicitly synthetic signature regression reproduces both
the completed-term failure and a changed residual about `h` rather than the
requested `boundary`. The repair must preserve arguments assigned while
discharging premises and validate completed applications before acceptance.
The projection-only qualification is retained as portable evidence; it is not
promoted to field success. Existing historical receipts and canonical target
identities are unchanged and gain no new assurance from a later repair.

No concrete added benefit from result navigation is established by this
attempt. Direct candidate checking made the missing premise explicit, but
plain Lean also exposed it. The next bounded cycle repairs valid-context
discovery and clarifies that the complete bundle is the ordinary inspection
entry point, then repeats the task in a fresh reader context. Full provenance
and profile expansion remain deferred. Performance and first-page changes
must earn priority from task evidence rather than the roadmap alone.

`attempts/` and `attempt-inventory.json` preserve original reports and complete
recorded commands, outputs and errors. `operator-supplements/` contains later
diagnostic and confirmation operations, clearly outside the original attempts.
Absolute paths in the receipts identify original inputs and stream locations;
the retained sibling files provide their portable copies.
