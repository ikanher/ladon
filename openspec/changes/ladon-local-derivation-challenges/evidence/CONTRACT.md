## Version and steps

Existing initialize default and v1 assess remain compatible. CLI init --derivations produces version2. API initialize(..., derivations=False). assess accepts 1 and 2. v2 status uses schema ladon-investigation-status-v2. All v1 validations apply with shared SourceReader bounds. Step work is scoped to a claim. A claim is suspicious if it has nonempty concern text, explicit derivation, or reviewed statement!=aligned or method!=same. This work is ordered before unrelated inventory/captured work, deterministic claim source order then step order.

A suspicious non-blocked claim missing its seven-field contract queues write-exact-contract; missing derivation queues decompose-derivation. Derivation shape: {author:nonempty string, steps:[...]}, 1..128 steps, <=4096 steps total. Each step: {id,startLine,endLine,quote,contract:{same seven v1 fields},rule:nonempty text,substitution:nonempty text,dependsOn:[unique earlier step ids], assessment?:{outcome:supported|refuted|unresolved,evidence:nonempty text}, arithmetic?:{see below}, challenge?:{reviewer,subjectSha256,outcome:supported|refuted|unresolved,evidence,witness?:assignment}}. Step spans stay within parent claim; quote exact; IDs unique per derivation, dependencies acyclic via earlier-only references. Empty dependsOn allowed. Source scope and reader bounds from v1 remain.

No/uncertain author assessment queues investigate-step. A resolved author assessment without challenge queues challenge-step. Challenger label must differ from derivation author (stripped labels compared); same label is invalid. Stale challenge digest is invalid. An unresolved or disagreeing challenge queues reconcile-step. Matching resolved outcomes complete step bookkeeping, not truth. A matching refuted challenge preserves a finding; arithmetic witness replay can independently expose a counterexample even when labels disagree. After steps are completed, unresolved original claim judgment still queues resolve-local-obligation or compare-formal-contract. Blocked claims retain v1 blockers and cannot hide other actionable claims.

step_subject(plan, claim, step) returns SHA256 of canonical JSON context: scope, original claim fields id/unit/startLine/endLine/quote/contract/formal (excluding workflow state, judgment, concern and blocker), derivation author, all steps with challenge fields removed, and target step id. Include every predecessor's contract, arithmetic and author assessment; changing these invalidates old challenges. Do not include clocks/other claims. JSON uses sort_keys=True,separators=(',',':'),ensure_ascii=False. Subject hash is an integrity binding, not a proof.

CLI investigation challenge --plan PATH --root ROOT --claim ID --output NEWFILE validates then exclusively writes a sanitized JSON packet: schema ladon-derivation-challenge-v1, claim id/source quote/contract/formal counterpart, derivation author, all step obligations and each subjectSha256. Omit assessments, prior challenges, judgments, concern text and arbitrary extra fields/repairs from exported packets. SHA bindings may commit hidden assessments but disclose no outcomes. No overwrite. Consumer manually saves a separate response and integrates challenge records into a copied plan; no automatic authoring/model invocation or identity verification.

## Exact rational witness

Public API ladon.rational_witness.check_witness(goal, assignment) returns JSON dict or raises ValueError. goal is exactly {variables:[names],premises:[predicates],conclusion:predicate}. Names unique ASCII [A-Za-z][A-Za-z0-9_]{0,31}, max32. assignment exactly maps every variable to a rational literal, no extras. Rational literal: nonboolean integer or string matching -?(0|[1-9][0-9]*)(/[1-9][0-9]*)?, max128 chars; floats/bools forbidden. AST expressions exactly {var:name}, {rat:literal}, or {op:add|sub|mul|div,args:[two expressions]}, {op:neg|abs,args:[one]}, {op:pow,args:[one],exponent:integer0..8}. Predicate exactly {op:le|lt|eq|ne|ge|gt,left:expression,right:expression}. At most64 premises, depth32,4096 AST nodes total and4096 bits per numerator/denominator intermediate. Validate full tree including predicates after false premises. Division byzero/undefined operations reject. No eval or user-code execution.

Result schema ladon-rational-witness-v1. status counterexample iff all premises true and conclusion false; outside-assumptions if any premise false; otherwise not-counterexample. Return premises and conclusion records with lhs/rhs exact rational strings and holds booleans. No sampled success or absence of counterexample certifies universal truth. validate_goal(goal) validates AST independent of an assignment. Values outside resource bounds reject rather than return mathematical outcomes.

CLI investigation witness --plan --root --claim ID --step ID --assignment JSONFILE validates v2 plan and checks the stored step arithmetic; never accept replacement goal from assignment. Result includes subjectSha256, claim, step, exact evaluations, source-interpretation nonclaims. Valid operation exit0 for all three mathematical outcomes, invalid input exit2. status/next/finish retain v1 exit semantics. Embedded challenge.witness is replayed against step arithmetic; refuted outcome with supplied non-refuting/outside witness is invalid. A real witness inconsistent with a supported outcome stays actionable and its checked finding visible. No witness means outcome/evidence are authored, not checked. Shared JSON load limit4MiB and duplicate-key rejection apply.
