# Proposal

## Why

The selected prose–Lean pair now has a checked norm bridge, but the current
prose contract producer accepts only the Nat profile, and the Real recognizer
requires a set-indexed bound. Its exact authored proposition elaborates but
cannot enter that grammar. Another wrapper around the existing interpretation
artifacts would not connect the pair.

## What Changes

- Reuse native source-map/interpretation artifacts to elaborate an attributed
  reading as a proposition, without asserting it as a theorem or axiom.
- Observe Real bound features with exact scope for both global and set-indexed
  predicates, keeping aliases/unsupported expressions and source qualifications
  explicit until their semantics are checked.
- Add a separately versioned authored Real representation and checked connection
  to admitted formal contracts. Preserve actual transport constants, assumptions,
  norm/carrier identities and source/implementation freshness.
- Exercise public production, inspection and exact connection on unrelated
  controls and the informed source pair. Preserve unsupported old-consumer paths.

Success is a source-bound authored Real reading with a replayable, explicitly
qualified connection result, not a new theorem or an automatic paper diagnosis.
The [specification](specs/ladon-real-prose-contracts/spec.md) owns acceptance.
General graph propagation and unfamiliar-source benefit remain parent gates.

## Capabilities

### New Capabilities

- `ladon-real-prose-contracts`: Typed, attributed Real estimate readings and
  evidence-bound connections to formal contracts.

### Modified Capabilities

None. Existing Nat and extracted Real formats keep their historical meanings.
The existing Real-bound child has not been synced into a main capability;
this child references its admission guarantees without rewriting them.

## Impact

Additive prose observation/production and connection modules, Lean proposition
elaboration support, explicit native consumer dispatch, public investigation
commands and focused tests. Reuse interpretation validation, source ownership,
process supervision and existing admission checks. No new package dependency,
Quux import, search algorithm, cache, paper edit or full-paper audit.

The user's continuation of Task 2.1 motivates this bounded integration plan.
Its evidence does not itself lift the wider runtime freeze; implementation is
limited to the behavior explicitly specified here, with no general frontier
activation or expansion of the completed Real-bound child's historical scope.
