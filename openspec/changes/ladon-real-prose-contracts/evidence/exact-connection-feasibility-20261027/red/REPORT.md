# Task 2.2 independent falsifier report

Scope: read-only review of the frozen Task 2.2 contract and existing producer, history, transfer, and source-goal APIs. No production/test/Lean/build execution and no original-source edits. Proposed tests only; public connection API is not frozen.

## Current evidence and seams

- `src/ladon/real_prose_native_production.py` reconstructs authored artifacts against the exact interpretation and observation owners, fixes `authority=none`, `admission=unresolved`, and `fidelity=attributed-unreviewed`; inspection remains historical and never does a fresh check. The existing authored tests cover rehashed promotions, crosswired interpretation/source-map refs, source changes, SQLite, and rejection by legacy/extracted consumers (`tests/test_real_prose_native_records.py`, `tests/test_real_prose_native_boundaries.py`). These are a good base, but none owns a checked connection.
- The source-goal API (`src/ladon/source_goal_capture.py`, `src/ladon/source_goal_completion.py`) captures a full structural goal, source span and bytes, local context, open declarations/options, compiled import inventory and toolchain. Completion re-captures and compares that context, checks a term at the original goal, then replays it and checks axiom coverage. This can supply a kernel-checked implication in one exact source context; a result from this API alone does not bind the two Task 2.2 input artifacts or establish their direction/owner relationship.
- Existing transfer is a useful precedent, not a reusable endpoint: `real_bound_native_transfer_check.py` enforces same source/context and orders explicit premises, while `real_bound_native_transfer.py` shares a deadline across re-admissions and reports `transferPremises=assumed`, `sourceTheoremProof=not-checked`, and `mathematicalFalsity=not-established`. Its profile only handles extracted bound transfers and source-shaped compositions. Authored global Real contracts with named operations, explicit specialization/norm/coefficient bridges, and a single arbitrary implication need their own owner-bound connection representation/checker.
- The older source-goal completion tests exercise original-context application, wrong terms, multiple goals, universes/instances, stale source and replay (`tests/test_source_goal_completion_*.py`). They do not check a pair of source/formal proposition owners, typed proposition-value versus declaration-type confusion, or a multi-stage shared deadline/output budget.

## Main falsification risks

1. **Owner swap and proposition/type confusion.** Bind both ordered input refs to exact native artifacts, then bind each owner to its fully elaborated Prop expression, declaration name/kind, source path+digest/span, context identity/import closure, and toolchain. Do not take `Prop` (the type of an authored `def : Prop`) as the authored proposition; do not confuse a formal theorem's proof constant with its declared type/proposition. A rehashed result must still fail if only one owner ref, declaration, path, type expression, or order is swapped. Two declarations with alpha-equivalent or identical pretty text are not interchangeable owners.
2. **Direction and route versus endpoint.** Preserve `formal -> authored` (or explicitly chosen opposite direction) as an ordered checked goal. Include a fixture where one implication is valid and its converse is not. Reject wrong direction as an unresolved/rejected chosen route with `mathematicalFalsity=not-established`; do not turn a failed completion, unsupported context, or timeout into endpoint falsity. If another route later succeeds, report it separately from the rejected route.
3. **Bridge substitution / dropped premises.** Every specialization, predicate identity, global/set adapter, norm conversion, constant change and local alias needs an exact typed goal and owner-bound check. The final goal must retain every supplied conditional premise and every quantified variable in the right scope. Rehashing a changed bridge owner, omitting one premise, or replacing the goal with a stronger unconditioned conclusion must reject. Existing transfer checks retain explicitly unproved premises; they cannot be silently elevated to facts here.
4. **Coefficient and scope drift.** Mutation tests should alter a literal loss, operation order, coefficient factor (`K*C` to `K`, `C*K`, or `L*C`), dependency scope (order-dependent factor made uniform), binder order/quantifier, or global/set-indexed domain. Each must fail the exact goal check or remain unresolved. Never flatten typed coefficient terms into metadata or claim a stronger bound from them.
5. **Textual prefix and import-context overclaim.** `sourceGoal` captures byte-exact source and import/toolchain context, but equal source bytes or a byte-prefix extension is only a candidate route. A suffix can shadow/open/rebind a name, alter namespace/options, or introduce a declaration with the same short name; imported declarations can have different owners under different closures. Require resolved declaration owners and exact structural types in the actual compiled context, and test shadowing, changed imports, changed open/namespace/options, unrelated same-name modules, and source drift. If a formal and authored owner cannot both be named/resolved in one supported checked context, retain an explicit unsupported-context residual; do not accept name+type metadata as proof.
6. **Historical fake-green and freshness.** Tamper a saved connection/check receipt, premise list, owner ref, context/toolchain identity, process status, or accepted-run result and recompute outer content IDs. Validation should reject impossible reconstruction; inspection must remain `freshCheck=false`/authority none and separate recorded history from current source freshness. Replay must re-run all required admission/bridge/final implication checks and refuse stale source/import/toolchain inputs. A self-consistent content hash is integrity structure, not evidence authentication.
7. **Budget and cleanup.** Start one monotonic deadline before any history validation, admission replay, bridge check and final implication; pass only remaining time to every nested process and stop after expiry. Apply the same RSS/output ceilings per supervised process and also cap aggregate retained request/response/receipt bytes, since several individually bounded stages can exceed 8 MiB in total. On timeout, RSS/output stop, malformed child response, or cancellation: kill/reap child trees, clean every staged file/workspace, preserve failure receipts within the output cap, emit no partial accepted connection, and do not auto-retry with a fresh budget.

## Minimal proposed red acceptance matrix

The first red should be small and public-API-facing, with generic fixtures unrelated to the target theorem names. Suggested single core test module after the API names freeze:

- **Positive generic Mathlib case:** use an actual pinned Mathlib source context with two unrelated, fully qualified declarations and different proposition owners. Establish one valid ordered implication through an explicit `by` term, retain the exact typed final goal and all binders, and assert separate author/formal refs, exact bridge/premise order, fresh check evidence, and unresolved theorem/fidelity limits. Include a simple true implication whose direction is unambiguous; do not use a profile-specific name or fixed loss.
- **Wrong direction / bounded rejection:** reverse that request and give a term that does not prove the reversed goal. Assert route status is rejected/unresolved, no checked authority, no connection artifact claiming success, and falsity remains not established. A bounded timeout or unsupported-context result has the same non-falsity rule.
- **Owner mutation table:** independently swap authored and formal artifact refs; substitute a same-text proposition from another module; substitute the proof declaration for its declared proposition/type; mutate the native interpretation/observation owner; and mutate only the ordered goal's structural type. Rehashing all outer IDs must not turn any into accepted evidence.
- **Bridge/premise mutation table:** remove each explicit specialization/predicate/norm/coefficient bridge, swap a bridge's exact owner, drop a conditional premise, and change its order/binder scope. The original positive should pass; each mutated request/result should reject or remain unresolved.
- **Semantic negative table:** wrong direction, wrong carrier (`Real`/`Nat` or function domain), global vs set-indexed scope, changed constant/operator, changed coefficient/loss, and an unsupported symbolic alias. Assert no theorem falsity or guessed scalar is inferred.
- **Context provenance cases:** positive exact same-context resolution; positive supported exact-prefix extension only if declaration resolution remains tied to the original owners; negative name shadowing, altered open/namespace/options, added/removed imports, changed source bytes, and unrelated module with same short names. Unsupported contexts must not be papered over by generated source that merely imports similarly named declarations.
- **Saved history:** round-trip a completed connection; tamper/re-hash the connection result, nested completion receipt, premise list and context identity; assert inspect is historical/no fresh authority and replay re-checks with current source. Mutated history must never replay as accepted.
- **Shared resources/cleanup:** inject deadline exhaustion during admission, bridge and final implication; inject RSS/output stops at each stage and cumulative output over limit; assert later stages do not run, wall-clock budget is not reset, no child remains, and all scratch dirs are cleaned. Preserve exact failure evidence without publishing a partial connection.

## Contract sufficiency finding

The contract's exact-owner, typed-proposition, fresh-replay, premise, history and bounded-execution requirements are appropriately strict. The proposed candidate rule “authored context equals or is an exact byte-prefix extension of formal source” is not sufficient as an acceptance predicate by itself: prefix bytes do not prove declaration resolution or proposition identity, and imported-source routes cannot rely on matching names. Treat it only as an early route filter, then verify both fully qualified owners, their exact typed propositions and every bridge in a compiler context whose source/import/toolchain identity is checked. The final kernel goal itself must visibly be the ordered conditional implication from the admitted formal proposition and all declared premises to the attributed authored proposition.
