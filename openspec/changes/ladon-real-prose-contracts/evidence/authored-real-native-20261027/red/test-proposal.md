# Task 2.1 authored Real native record: adversarial test proposal

This is a consumer-level red plan; the new public API names and field spellings are intentionally left to root integration. Reuse the source-bound `reading(project)` / `context()` constructors and `real_prose_recognition` fixture in `evidence/prose-shape-v2-20261027/runtime/tests/test_real_prose_recognition.py`; it has actual global and set-indexed owners, positive normalization checks, and wrong-product/shift controls. It is especially useful because a “recognized” result still correctly has `admission == unresolved` and `contract is None`. Reuse the observation contract fixture for source maps/interpretation and CLI invocation. For native persistence/consumer setup, adapt (do not copy opaque snapshots from) `evidence/qualification-20261027/qualify_native.py` and `evidence/native-admission-20261025/native_cli_roundtrip.py`; those exercise existing real-bound native record, SQLite, report and legacy-consumer owners. Run tests from an isolated runtime copy against those existing modules; do not mutate the shared runtime or product DB.

## Required assertions

1. **Public production cannot be told what to admit.** Produce generic and selected Real records from original interpretation + context. Generic unsupported shape, wrong product alias, nonlinear shift, missing coefficient nonnegativity guard, or unresolved normalization must return an unresolved/unavailable record with no `proofir.contract`. Supplying an extra caller field such as `admitted`, `admission`, `features`, `loss`, `origin`, or a purported recognition receipt must be rejected by closed request validation (or be ignored without changing result); none may produce admitted state. A valid recognized record must still state unresolved admission and unreviewed fidelity.

2. **Forged admission fails at every boundary, even after recomputing hashes.** Starting from a valid record, independently mutate admission/status, authority/fidelity, feature loss, guards, canonical term, recognition snapshot, nested observation, interpretation/source-map ref, and producer/toolchain owner. Recompute outer identities using the production identity helper after each edit. Historical inspection may validate only closed stored syntax/integrity; it must never become fresh or authorized. Native artifact and batch validators must reconstruct the same record/feature values from exact nested owner artifacts and reject every altered variant rather than trusting a valid outer digest.

3. **Owner cross-wiring is rejected.** Generate two valid readings from the fixture, changing only selected alternative/reading id, source quote, product alias, or global versus set-indexed scope. Swap one at a time the observation, recognition, interpretation, source-map, and selected-alternative refs between records; also construct a hybrid with individually valid nested artifacts from each. Require native batch validation and root-aware inspect/replay to reject owner mismatch. Two distinct alternatives may coexist in one batch only when each record has its own exact source/interpretation/observation/recognition chain, and explicit `alternativeId` plus author are retained; dangling or duplicate-conflicting refs fail.

4. **Origins and scope are bound, not descriptive labels.** Mutate source range/path/quote digest, selected context file/module/scope, binder ids/order, global↔set-indexed scope, `originPath`, normalization path/scopeCount, coefficient permissions, or selected multiplication instance. Rehash all enclosing identities. Fresh replay must fail on changed source/context/runtime/toolchain/import custody, and validators must reject altered origin/scope/features before replay. Explicit set binder must not be dropped; a global record must not acquire set-scoped evidence. Every conditional premise and bound-nonnegative guard (including duplicate occurrences) must remain represented.

5. **Historical versus fresh is observable and one-way.** Historical inspect without root/context returns syntax/history only (`authority: none`, `freshCheck: false`); it must not be accepted by replay or a semantic operation requiring fresh evidence. Root-aware inspect/replay on unchanged owners re-runs exact recognition and bounded checks; mutate source bytes, imports, toolchain, interpretation, context, or runtime identity and require stale rejection. Rehashing the old record cannot repair staleness. Resource/timeout stop yields no dependent native record and does not reset the shared deadline between observation, recognition, custody, and native production.

6. **Closed, bounded native codec has no alternate parse.** For any chunked historical representation, round-trip exact nested JSON identity, then reject unknown/missing keys, duplicate keys, malformed JSON, invalid UTF-8, noncanonical encodings, reordered/overlapping/missing chunks, truncation, overlong chunks, invalid count/length/hash, inconsistent reconstructed snapshot id, extra trailing bytes, and depth/size/string limit overflow. Enforce the existing depth-64, artifact-8-MiB, batch-32-MiB, string-1-MiB, no-float constraints without globally relaxing limits. Test boundary sizes and a near-limit legitimate record so implementation does not only pass tiny/success-stub cases.

7. **SQLite/report are lossless and transactional.** Insert a batch with two alternatives, export report, re-import/rebuild into a temporary DB, and compare canonical full records, all refs/provenance/author/alternative ids, reconstructed identity, relevant indexes, and integrity-check results byte-for-byte or structurally as their APIs promise. Inject failure after partial insertion and during report reconstruction; assert transaction rollback leaves no rows or dangling refs and rebuild is deterministic. Tamper DB/report owner refs and hashes; integrity/rebuild must reject rather than silently dropping or substituting source/recognition owners. Do not expand schema without measured need.

8. **Old consumers fail closed.** Feed valid new authored Real native record into each existing Nat/Real semantic reader, extractor, comparison/propagation path, and old-profile validator. Require explicit unsupported-profile/schema diagnostics with no extracted Real/Nat relabel, admitted rule, comparison, propagation, theorem/falsity signal, or fallback to an older parser. Existing native schemas and known valid fixtures remain accepted unchanged.

## Implementation traps for review

- A content hash proves byte identity, not that a record's alleged admission or feature is valid. Fresh public construction must derive from current source owners and recognition; batch validation must join exact owner artifacts and recompute features.
- Matching only the formula digest is insufficient: source-map/interpretation ids, selected alternative, context scope, binders, guards, origin paths, coefficient permissions and recognition receipt all belong to the chain.
- Do not call an observed/recognized syntax feature a theorem, admitted Real bound, or semantic connection. Task 2.2 is separately gated.
- A history codec must preserve *all* exact owner payloads; replacing large records with a success flag or digest-only stub defeats round-trip and replay requirements.
- Probe legacy consumer dispatch by their public reader APIs and assert explicit unsupported outcome; a validator accepting the new generic envelope does not establish safe semantic consumption.
