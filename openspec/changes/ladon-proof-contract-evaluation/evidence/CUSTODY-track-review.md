# Evaluation contract review

The three-track split and promotion arithmetic are understandable, but several scoring details need an explicit freeze before execution.

- **Case versus claim unit.** B says 12 cases but scores per-feature extraction and final comparisons. Define a fixed feature inventory per case and whether multiple claims can produce more than one TP/FP. C requires a fragment with multiple candidate claims; score at most one nominated target claim per case, while preserving every additional assertion for FP/adjudication accounting.
- **A classification vocabulary.** The design says all 24 receive a “specified classification” but does not define the labels or required evidence per class. Freeze labels for mismatch, valid, and unknown/unsupported; distinguish an honest abstention from a wrong classification. Define whether the four unsupported/truncated cases can ever be counted as FP.
- **B truth and extraction denominator.** Ten supported and two unsupported cases are stated, but “supported” is not operationalized. Freeze the supported feature list and require each feature to be traceable to source text and formal syntax. Keep case-level end-to-end success separate from feature precision/recall and fidelity; unsupported cases stay in the 12-case denominator.
- **C fault/control truth.** “Fault” and “valid control” need source-level criteria and explicit provenance. The protocol now requires natural, original discrepancies and forbids modified pairs from counting as discovery. If the intended C track permits constructed faults, it must be labeled a constructed capability test and cannot support a real-source discovery claim.
- **False accusation and unresolved handling.** The parent names zero false accusations but does not say whether this is per claim or per case, or how unresolved adjudication counts. Protocol v1 defines any unsupported discrepancy assertion as an FP and unresolved findings as no TP/control credit; retain these case-level and claim-level records.
- **Budget and order.** The design specifies 90 minutes per 12-case arm while A has 24 cases and both A/B precede C. State explicitly whether A receives two 12-case budgets or one 24-case budget, whether the budget includes setup/checker time, and whether the case order is shared across arms. Freeze the randomization seed and actual order.
- **Baseline comparison.** “One more confirmed fault than baseline” requires identical C inputs and admissication criteria in both arms. Preserve paired case results; don't compare aggregate totals if one arm timed out or saw different evidence.
- **Adjudication independence.** “Independent adjudication” needs a named role and a rule for conflicts. The adjudicator should see frozen first reports and source evidence, but not the key's expected class until their initial judgment is recorded. Record their evidence and any disagreement.
- **Discovery gate scope.** Zero FPs, 4/6 faults, 5/6 controls, and +1 over baseline are clear once units are fixed. Keep this as an engineering decision for this fixed portfolio; it does not estimate broad population accuracy.

Custody status for this pass: blocked. The reviewed local inventory contains fixtures and prior project evidence, but no independently sourced corpus with proven family separation, admissible original prose, actual formal counterparts, and six natural faults plus six controls was established. No source fragments or answer labels were admitted. This is not a claim that such sources do not exist elsewhere.

## Review of the frozen parent protocol

The frozen JSON matches the planned counts (A 24 = 12 faults + 8 controls + 4 unknown; B 12 = 6 matches + 4 discrepancies + 2 unsupported; C 12 = 6 faults + 6 controls), names Luna medium, pins seed 20261018, fresh contexts, 90 minutes per arm, 12 GiB, and preserves first reports. The promotion threshold is acceptable as a bounded engineering gate, provided it is reported without a population-accuracy or statistical-significance claim.

One budget ambiguity should be resolved before A runs: “90 minutes per arm” gives A twice as many cases as B/C in the same wall time, while the design text says 90 minutes per 12-case arm. Choose and record either (a) 90 minutes per track-arm, accepting different time per case, or (b) two 12-case A batches each with 90 minutes, stating reset/context/order rules. Baseline and enhanced must get the same choice and the same exact case order.

The metric list should explicitly include unsupported selections and unresolved adjudications, as the design requires an unresolved queue and the case-level denominator must remain auditable. Define FP as the promotion rule's “false accusation” unit and state whether it is case-level or assertion-level. My protocol uses any unsupported discrepancy assertion as a false accusation, with all assertions retained and the C gate evaluated per case.

C's JSON status is still `custodian-preparation-pending`; update it to blocked/nonblind if no independently admissible set is available at runtime freeze. A blocked C is not a failed implementation gate, but it leaves detection benefit unestablished and bars the broader trial. No cases were admitted in this custody pass.
