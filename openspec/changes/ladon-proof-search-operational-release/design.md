## Context

Eight implementation packets change private schema, public statuses, lineage views, ranking, and report defaults. The release packet owns integration, ordinary CLI behavior, documentation/skill synchronization, and evidence that improvements hold outside unit modules.

## Goals / Non-Goals

**Goals:** integrate without caller-specific surfaces, validate installed behavior, synchronize guidance, run portable gates, and repeat read-only first-hand calibration.

**Non-Goals:** modifying Matrix-Factorization Lean source, hiding incompatible generations, or claiming cross-host absolute performance.

## Decisions

1. Preserve ordinary CLI commands and version public payloads at changed semantic boundaries.
2. Make portable fixtures authoritative; treat Matrix-Factorization as fingerprinted observational calibration.
3. Update the maintained skill first, validate it, then synchronize requested project-local copies without overwriting unrelated repository work.
4. Record a release evidence manifest containing commands, identities, plans, storage, timing, RSS, exits/signals, and omissions.

## Risks / Trade-offs

- [Many packets integrate at once] → dependency ledger, byte-identical umbrella/child specs, and strict per-child validation.
- [Sibling project is dirty or unavailable] → all calibration is read-only and optional; portable gates remain authoritative.

## Migration Plan

Apply children in ledger order, rebuild incompatible disposable databases, retain explicit compatibility metadata for public transitions, then run installed and calibration gates.
