## ADDED Requirements

### Requirement: Ordinary CLI surfaces integrate the hardening program
Humans, scripts, editors, and models SHALL use the same `search`, `explain`, `consumers`, `constructor`, architecture, and theorem-lineage commands; no caller-specific command or hidden evidence path SHALL be added.

#### Scenario: Installed wheel is exercised
- **WHEN** release tests invoke every hardened operation from outside the source tree
- **THEN** installed behavior, schemas, exits, streams, progress, and atomic outputs match repository tests

### Requirement: Documentation and skill state operational limits
Documentation and the maintained Ladon skill SHALL explain incompatible-schema rebuilds, base versus complete budgets, coverage-sensitive empty results, warm lineage summary, finite lineage caps/timeouts, owner projection, ranking evidence, and lexical/Lean/ProofIR authority boundaries.

#### Scenario: Caller has an old database
- **WHEN** status reports incompatible schema
- **THEN** guidance directs an explicit rebuild and does not suggest querying the generation as fresh

### Requirement: Portable integrated gates are authoritative
Release SHALL run all child suites plus schema, foreign-key, integrity, populated query-plan, statistics, size, deterministic, CLI, process, output, and full Python quality gates without sibling repositories.

#### Scenario: One access-path gate regresses
- **WHEN** a selective populated query becomes a full scan
- **THEN** the integrated release fails even if functional output snapshots still match

### Requirement: Matrix-Factorization calibration is fingerprinted and read-only
Observational calibration SHALL record repository/toolchain/source/database identities, commands, exit or signal, elapsed time, peak RSS, output bytes, table/index bytes, plans, and result quality without modifying Lean source.

#### Scenario: Warm lineage is recalibrated
- **WHEN** the stopped-region theorem closure is available
- **THEN** summary and bounded traversal produce terminal records and measured improvement against the first-hand baseline

### Requirement: Compatibility and rebuild behavior are explicit
Public result changes SHALL be versioned, private schema changes SHALL require disposable rebuild, and deprecated compatibility fields SHALL carry removal metadata rather than silently changing meaning.

#### Scenario: Old consumer schema is requested
- **WHEN** transition support remains enabled
- **THEN** the response marks deprecated semantics and supplies the new authoritative coverage/status fields
