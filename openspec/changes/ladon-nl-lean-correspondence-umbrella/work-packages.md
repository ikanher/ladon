# Work packages and acceptance gates

These packages execute inside this umbrella. They are not claims of completed
implementation. [tasks.md](tasks.md) is the single progress record. If a concrete
package is split into a child change during implementation, replace its detailed
umbrella tasks with links to that child, its owning requirements, and acceptance
evidence; do not maintain duplicate checklists. No child is required merely to
begin the already specified first vertical.

## M1: the first complete correspondence

M1 is the barrier before generalized extraction and search. It requires all of:

- A source quote and a structured attributed interpretation with explicit scope.
- An actual observed formal application, not a pasted theorem summary.
- Explicit object correspondence and generated premise/conclusion obligations.
- A successful local Lean replay on the faithful portable control.
- A checked negation or premise-satisfying counterexample for the incorrect
  portable interpretation; failed tactics alone do not satisfy this condition.
- The selected real pressure-datum application and a source-faithful account of
  what it supplies to the real page-3 passage. Incomplete physical/off-axis
  transfer remains visible and must not be scored as checked correspondence.
- Public command output with native artifacts, independently inspected source
  fidelity, and one executable guide reproducing the supported behavior.

The real-source result may be qualified or unresolved while M1 establishes the
mechanism on checked controls. M1 does not establish detection of the historical
reported bug, and no downstream package can relabel it as such. If even the
portable extraction/checking path cannot satisfy M1, stop broad expansion, keep
the failed observations, and revise the consuming design explicitly.

## Interpretation and provider test matrix

Use actual Lean proofs with controlled mutations where appropriate. Cover:

| Family | Fault or gap | Faithful control |
| --- | --- | --- |
| Quantifier/witness scope | A witness dependent on a parameter is presented as common | Correctly dependent witness and consistently renamed binders |
| Domain and premises | Dropped domain restriction or unavailable side condition | Exact restriction and genuinely supplied premise |
| Object representation | Source and formal expressions denote different objects | Checked transport between two representations |
| Local versus parent validity | A failed predecessor is used to refute a valid conditional | Separate conditional support and unresolved parent support |
| Method correspondence | Same endpoint hides a different argument | Valid alternative proof reported as alternative, not false |
| Ambiguity | Evidence for one reading is transferred to another | Multiple readings and their individual outcomes |
| Provider completeness | Only one premise branch is expanded | All AND branches or explicit residual frontier |
| Provenance | Changed source, context, map, or checker reuses old acceptance | Reuse only with exact unchanged input identities |

## E: bounded evaluation protocol

Freeze one pilot of eight independently selected short passages with actual Lean
sources: four faulty argument passages, two faithful controls, one valid
alternative-method control, and one explicitly ambiguous control. At least two
inputs include surrounding nonfaulty reasoning so the tested inference is not
preselected for the auditor. The curator retains justified outcomes separately;
case order and classifications are undisclosed. A faulty argument need not imply
a false final theorem. Count the two kinds separately.

Use fresh contexts for each arm on each case: current Ladon versus ordinary local
source/Lean tools, with the same model and reasoning configuration, source access,
cache state policy, and 15-minute case budget including independent review and
reporting. Run case/arm order from a recorded seed. Keep curators, developers,
and key holders out of blind auditor contexts. A reviewer receives source and
sanitized obligations, not prior verdicts. Record reviewer participation in both
arms so multi-agent help is not silently unique to Ladon.

Score exact faulty-inference localization, valid evidence, correct controls,
interpretation errors, formal gaps versus refutations, false positives,
abstentions, source selection, elapsed time, tokens where observable, and tool
cost. Aggregate mechanically from normalized case rows and check consistency.
Unresolved references require adjudication rather than a forced verdict. Retain
unavailable tooling and timeout outcomes in denominators. Do not substitute
post-hoc easier cases or repeat until a favorable result appears.

The pilot can establish only a pilot-scoped capability or benefit observation.
Report whether assistance improves justified findings without more false alarms,
or preserves findings at lower observed cost. Otherwise report the unmet benefit
objective. Shared filesystem separation is procedural unless actually enforced.
This phase includes no new full-paper run and no search for target-paper answers.

## Verification ownership

Use the current development checkout explicitly for public command tests. Each
package owns its focused regressions and runnable documentation. Reuse unchanged
parent checks rather than repeatedly running the whole suite. After the final
production edit, run affected parent consumers and obtain an independent
integrated review under the applicable engineering skills. Lean-backed acceptance
requires actual pinned Lean execution; missing tooling cannot be a silent skip
for a required capability gate. No tests or implementation are claimed run by
this planning-only packet creation.
