# Domain acceptance

The bounded mathematical contract domain is implemented and independently
reviewed. [Validation](VALIDATION.json) records source hashes and exact check
scope; [the review](INDEPENDENT-REVIEW.json) is the frozen post-integration
auditor response.

The implemented boundary is authored, profile-structural comparison and native
storage. It preserves scope, explicit constant choice points, correlated
permissions, unknown features, source references and result authority. A checked
profile comparison cannot be used as a formal derivation or source proof slice.
The source-to-summary binding remains explicitly unchecked; future consumers
must establish the source fidelity and application evidence they need before
pruning formal proof alternatives or discharging correspondence obligations.

Verification: 412 broader Python tests passed with no failures or skips; an
additional normalized-storage test passed. Two Rust boundary tests passed.
Scoped strict Python quality and Ruff passed. The actual pinned Lean fixture
compiled under the 12 GiB process limit; its named axiom judgments contain no
custom or sorry axioms. See [the Lean receipt](LEAN-FEASIBILITY.json).

TDD exposed missing implementation, missing source-binding limitations, absent
constant choice points and duplicated constant/witness permission ambiguity.
Each latter defect received a failing regression before its fix. A root-authored
fixture alias was corrected without changing frozen assertion files; its old
helper bytes and frozen revision history are retained on the task board.

This acceptance does not establish source extraction accuracy, arbitrary
analytic norm semantics, unfamiliar-source detection benefit, or completion of
the parent umbrella. Only the comparison analysis stage is currently admitted.
