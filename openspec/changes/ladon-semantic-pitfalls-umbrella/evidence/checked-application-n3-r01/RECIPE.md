# Checked source-claim application recipe v1

Purpose: under an explicitly attributed interpretation, obtain a checked application and conclusion transfer from the source assumptions, or retain its actual remaining obligations. The premise ledger explains the route. This experimental recipe uses existing Ladon and Lean operations; it is not a new production API.

1. For a fresh exercise, read only the passage and necessary definitions before exposing a candidate theorem/crosswalk. Record original objects, definitions, parameter domains, assumptions, quantifiers, conclusion and uncertain readings. Freeze that file's bytes. Existing author exposure in these cases must be disclosed; do not claim it has been undone.
2. After exposure, inspect the actual formal declaration and context. Record each identity/object transformation and any interpretation revision as a separate attributed entry. Preserve source claim identity; a repair is a different claim.
3. In an isolated local working project, encode the source context and conclusion as a Lean example/claim, importing the retained owner. Keep original source premises only. Map all theorem arguments at one consistent parameter assignment, preserving dependent order and lets. Use application observations for diagnosis; the same declaration's printed type is not a substitute for the source goal.
4. Account for each argument via a cited source attribution, checked derivation or unresolved obligation. Include relevant implicit/instance context via the justified encoding; implementation typeclasses need not have literal prose counterparts. Preserve equivalent/stronger source assumptions and explicit conditional reasoning. Do not import missing premises, False or the desired conclusion.
5. Build the full application followed by conclusion transfer. An intermediate accepted application or rows individually valid at different assignments cannot establish completion. For an alternative route, bind the transformed objects and transfer back to the original conclusion. A measurable-limit claim needs its separate bridge.
6. Use existing source-goal capture and completion to check that proposed whole term in the actual source context. Bind capture/environment, source digest, term, completion/replay/trust status and all residuals. A source placeholder used to expose a goal is not a proof and cannot supply completion authority; reject trust in sorryAx or the internal target. Inspect semantic status rather than process exit zero. If capture/completion cannot handle the profile, report the exact failure and evaluate an ordinary Lean proof of the complete source-context proposition as a disclosed alternative, not a native completion success.
7. If refuting, check an independent assignment/model satisfying every original premise and violating the original conclusion. Realize scalar models in the actual probability setting. Finite experiments do not establish an infinite-horizon failure. A selected-route gap alone is not a refutation.
8. Report source interpretation, formal support and unresolved scope separately. The selected route cannot be completed while application or transfer obligations remain. Positive faithful/derived/alternative controls must receive justified support; blanket abstention does not pass qualification. Preserve first reports, failures and effort limits.
