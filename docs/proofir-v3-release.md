# ProofIR v3 release contract

The ordinary installed command is:

```text
ladon proofir validate ARTIFACT.json
ladon proofir canonicalize ARTIFACT.json
ladon proofir inspect ARTIFACT.json
```

These operations are bounded and do not start Lean. Lean checking remains an
explicit supervised operation represented by a check-run observation. The
ordinary command `ladon proof-search check candidate --module MODULE --goal
GOAL --candidate DECLARATION --format json` checks one declaration application
against one closed goal. Its default compact projection first registers exact
environment/check-run/derivation or attempt artifacts in a separate user-cache
registry, proves that its artifact-qualified references resolve, and omits the
artifact bodies from transport. `--projection audit` returns the unchanged full
artifact population. An application with remaining premises retains typed
substitutions, residuals, context, and an incomplete attempt-log. Bounded
failures publish no accepted artifact. The native-v3 artifact is the only input
that may contribute semantic projection rows. Unsupported or stale artifacts
must be regenerated by their producer, validated, and then used to rebuild
disposable indexes.

Portable fixtures and installed-command tests are release gates.
Matrix-Factorization is an external calibration target. Quux is a separated
research playground and is never inspected, executed, imported, or used for
calibration by Ladon. Portable Ladon-owned fixtures enforce this boundary.

## Rust reference boundary

The `rust/` workspace is a validation and projection-parity reference, not a
production replacement. Deployment keeps Python as the fallback until the
cross-language corpus covers diagnostics, normalized rows, SQLite plans, and
bounded graph queries. A release may roll back by disabling the Rust adapter;
canonical artifacts and the Python SQLite projection remain authoritative and
rebuildable. Rust accepts opaque Lean payloads and never invokes Lean or Quux.
